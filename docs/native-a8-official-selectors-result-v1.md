## Corrections demonstrated by the comparisons

1. **Owned object identity.** A purchased relic remained visible in the shop
   catalog while its acquisition selector was active. The native adapter gave
   that same object a second public identity. Shared inventory projection now
   joins only an exact native object reference, across both surfaces and reads.
   Matching names or definitions never merge different physical copies.
2. **Ordered execution.** Connector33 required all original cards to remain
   selectable even after native selection had started. Connector34 confines
   complete-domain validation to publication and uses the current remaining
   domain during execution. Local planning still delivers zero game inputs.
3. **Reward potion views.** The official capacity view hardcoded a bottle as
   unusable while its checked belt view allowed use. It also exposed duplicate
   discard aliases. Connector35 derives both views from the same checked bottle
   facts and retains the canonical game-owned discard path.
4. **Executable enchant answers.** The frozen enchant screen's confirmation
   callback requires at least one selected card, even though its stored
   preference minimum is zero. Connector36 and the new native planner publish
   the executable minimum of one for that qualified enchant owner. Other
   zero-capable selector families retain their own rules. The game callback is
   unchanged; no private bypass was added to make an empty answer complete.

The previous native empty-answer result remains historical evidence of headless
