# Fixed-budget combat search

The first search baseline is `isolated-root-uct-terminal-victory-v1`. It connects the admitted,
MIT-licensed EvanGambit simulator through SpireShift's common public `EnvironmentAdapter`; the
upstream checkout and compiled library remain external.

This is root UCT, not a full tree MCTS claim. Each simulation restores the same public checkpoint in
a fresh process, resamples one hidden world, applies one root candidate, and follows the declared
baseline policy to a terminal run outcome. UCT allocates later simulations using conservative
terminal-victory means. A crash, timeout, or rollout truncated at the hard transition limit remains
in the candidate's attempted count and contributes zero to its conservative value.

## Paired tiers

One suite captures a combat state as:

- the run seed and public action-ID prefix;
- patch and complete ruleset identities;
- the expected public state hash; and
- the ordered legal candidates.

It then runs `shallow`, `medium`, and `expensive` budgets from that exact checkpoint. Budgets are
strictly increasing and the shallow budget must visit every legal candidate. Simulation seeds and
root assignments are nested: the first *N* samples of a larger tier equal the *N*-sample tier. This
makes recommendation changes attributable to added computation rather than a different state or
unpaired random worlds.

Every tier records candidate visits, conservative and completed-only terminal values, outcome
variance, transitions, sampled worlds, unique seeds and terminal states, failures, worker CPU time,
wall time, mean latency, and p95 latency. The report keeps the selected action aligned to the source
legal-action order and carries explicit EvanGambit/MIT attribution when that backend is used.

## Commands

A short test-only suite is useful for checking a machine without making a gameplay claim:

```bash
uv run spireshift search fixed-suite artifacts/search/tactical-smoke \
  --backend tactical_mock \
  --shallow-simulations 3 \
  --medium-simulations 4 \
  --expensive-simulations 5 \
  --workers 4 \
  --maximum-rollout-steps 8
```

A production suite requires the pinned EvanGambit checkout and the admitted manifest generated by
the backend-admission workflow:

```bash
uv run --extra evangambit spireshift search fixed-suite artifacts/search/evangambit-seed-0 \
  --backend evangambit \
  --upstream-root /path/to/evangambit-sts2 \
  --manifest /path/to/evangambit-admitted.json \
  --run-seed 0 \
  --combat-state-index 0 \
  --shallow-simulations 16 \
  --medium-simulations 64 \
  --expensive-simulations 256 \
  --workers 8
```

The capture policy deterministically advances from reset to the requested public combat-decision
index. An exact action prefix can be supplied with repeated `--action-prefix` arguments when a
specific recorded state is required.

Run production suites through `spireshift resources run` so the fixed-search report has a separate
hardware and cost sidecar. Generated search evidence belongs under `artifacts/` and is not committed.

Audit a completed suite with:

```bash
uv run --extra evangambit spireshift search verify-fixed \
  artifacts/search/evangambit-seed-0/fixed-search-report.json
```

Verification checks the content identity, common checkpoint, tier order and budgets, nested paired
samples, action alignment, candidate aggregates, timing aggregates, worker-report digests, and every
immutable task/result. It then replays every completed simulation. On a production suite this is a
second long-running job and must be launched deliberately.

## Claim boundary

The checked tactical fixture proves the orchestration, accounting, pairing, and replay contracts.
It says nothing about STS2 search quality. A compute-versus-quality claim requires held-out combat
states plus a separate seed domain that independently grades every candidate; that experiment is
tracked by issue #7.
